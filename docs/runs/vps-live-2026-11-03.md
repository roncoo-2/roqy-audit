# roqy VPS live audit — pilot run (live-infra-audit skill)

Date: 2026-11-03. Host: ubuntu-8gb-nbg1-1 (Hetzner), kernel 6.8.0-139, up 45 days. 20 containers running.

## Findings

### L1 — confirmed, P0: Nginx Proxy Manager admin UI (port 81) reachable from the internet
Evidence: `ss -tlnp` shows docker-proxy on 0.0.0.0:81; `curl -sI http://178.105.86.15:81` returns HTTP 200 openresty.
Consequence: admin login panel exposed to the whole internet, brute-force and CVE target. Standard NPM practice is to firewall 81 or bind to localhost and use an SSH tunnel.
Fix: `ufw deny 81` (or bind 127.0.0.1:81 in compose), 10min.

### L2 — confirmed, P0: Supabase backups empty
Evidence: `/backups/supabase/daily|weekly|monthly` all total 0. Cron runs backup.sh daily at 02:00, system tier has fresh files.
Consequence: the customer-data store (Supabase) has no restorable backup despite the backup script existing.
Fix: debug why the supabase dump step produces nothing (likely missing DB URL in backup-config.sh), then one restore test. 1-2h.

### L3 — confirmed, P1: root filesystem 88% full
Evidence: `df -h /` = 63G/75G used, 9.1G free.
Consequence: disk full breaks Docker builds, logs, and DB writes.
Fix: prune docker images/build cache on /mnt, move heavy dirs to the volume, 1h.

### L4 — confirmed, P1: firewall inactive
Evidence: `ufw status` = inactive. Ports 22, 80, 443, 81, 3040, 6006, 631, 8899, 8889 all bound publicly.
Consequence: every listening service is internet-reachable; only obscurity protects the python debug/agent ports (6006, 8899, 8889).
Fix: enable ufw with allow 22/80/443, deny the rest, verify each service after. 30min. Do together with L1.

### L5 — confirmed, P1: SSH password authentication enabled, root login yes
Evidence: /etc/ssh/sshd_config.d/50-cloud-init.conf: `PasswordAuthentication yes`; sshd_config: `PermitRootLogin yes`.
Consequence: root password brute-force over SSH is possible if a password is set.
Fix: set `PasswordAuthentication no` (key-only), keep PermitRootLogin prohibit-password. 15min, verify key login before closing session.

### L6 — confirmed, P2: php2shell-target container has restart policy `no`
Evidence: `docker inspect` — only container without always/unless-stopped.
Consequence: stays down after reboot. It is a lab container, low impact.
Fix: `unless-stopped` or accept as-is.

### L7 — confirmed, P2: CUPS listening publicly on 631
Evidence: `ss -tlnp` 0.0.0.0:631 cupsd. No printer on a server.
Fix: `systemctl disable --now cups` (covered by ufw too).

## Rejected / clean

- TLS roqy.io: valid until 2027-01-02, >14 days left.
- Restart policies: all prod containers always/unless-stopped except L6.
- Failed systemd units: none.
- Memory: 4.8G available of 7.7G, healthy.
- Backups system tier: fresh (today 02:00), retention tiers working.

## Order of execution

2. L2 supabase backup fix (1-2h).
3. L5 SSH key-only (15min).
4. L3 disk cleanup (1h).
